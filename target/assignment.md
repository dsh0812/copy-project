## 0. 作业概览

### 0.1 任务

在课堂演示项目 `one-stop-research-vscode-llm/demo-project` 的基础上，用 AI 完成一次完整的**研究闭环**：

* 先复现主回归，再做**常规 + 研究主题特定的 DID 稳健性检验**；
* 在此过程中**设计 Prompt（保存为 Markdown）、写一个 Skill、设计一个综合评估 Agent**；
* 对输出**至少进行两轮迭代**，使其具备**一般适用性**；全程用 **Git** 版本控制留痕。
* 将结果推送到你的Github/Gitee 仓库，提交仓库链接即可。

`注意`: 重点看**设计质量与反思深度**，而不是看文件数目和回归次数。

### 0.2 研究背景（你作业的“研究对象”）

课堂演示项目模拟的研究问题是：

> **数字化转型是否提高了企业全要素生产率（TFP）？**

- 数据：合成企业面板，2016–2024 年，360 家企业，4 个行业、3 个地区。
- 处理：处理组企业于 **2020 年**开始数字化转型（`digital` 从 0 变 1），对照组从未转型。
- 主回归设定：

$$
\log TFP_{it} = \alpha_i + \lambda_t + \tau\, Digital_{it} + X_{it}'\beta + \varepsilon_{it}
$$

其中 $\alpha_i$ 为企业固定效应，$\lambda_t$ 为年份固定效应，$X_{it}$ 包括资本密集度、
出口占比与所有制，标准误聚类到企业层面。

- 已有输出（`output/`）：`stata_did_results.csv`（主估计）、`stata_event_study.csv`（事件研究）、
  `stata_placebo_results.csv`（安慰剂）、`digital_parallel_trends.png`、`digital_event_study.png`。

## 2. Part A：用 Prompt 驱动 DID 稳健性检验（保存 Markdown）

### 2.1 第一步：先定义识别目标

参照 Day 3 上午的因果推断速览——**在没有明确估计量之前，不要让 AI 急着跑模型**。
在开始任何稳健性检验前，先在 `output/estimand.md` 中写清楚：

| 项目            | 你的回答                                             |
| :-------------- | :--------------------------------------------------- |
| 处理组 / 对照组 | 谁被处理？谁是对照？                                 |
| 处理时间        | 何时开始处理？是否交错？                             |
| 目标估计量      | 平均处理效应（ATE）？还是处理组平均处理效应（ATT）？ |
| 关键识别假设    | 平行趋势；无预期效应；无溢出                         |
| 主要威胁        | 哪些因素可能违背上述假设？                           |

这一页写好后，才进入稳健性检验。

### 2.2 复现主结果

写一个“四要素”Prompt 复现主回归，确认你的基线系数与 `output/stata_did_results.csv` 一致。

**四要素模板**（每张检验 Prompt 都要包含这四项）：

```text
【目标】用 data/raw/digital_transformation_firm_panel.csv 估计/检验……
【边界】这是合成数据演示，结果不能解释为真实因果证据；不要虚构文献；只读 data/，不修改。
【验证】输出应包含……（具体指标/文件）；系数符号与量级应……；若输出异常请说明。
【汇报】汇报：系数、标准误、显著性、样本量、以及你的观察（是否符合预期、可能的问题）。
```

### 2.3 常规 DID 稳健性检验

对每一项，你都要：**写 Prompt → 运行 → 观察 → 输出结果文件 → 把 Prompt 存为 Markdown**。
推荐用 Python（`statsmodels` 的 `PanelOLS` 或 `smf.ols` + `C(firm_id)`/`C(year)` + `cov_type="cluster"`）。

| #  | 检验                       | 统计设定（提示）                                                                                          | 判断标准                       |
| :- | :------------------------- | :-------------------------------------------------------------------------------------------------------- | :----------------------------- |
| R1 | **平行趋势正式检验** | 在事件研究回归中加入处理前各期虚拟变量，做**联合检验**（`test` 处理前系数全为 0），报告 F 与 p 值 | 处理前系数联合不显著（p 较大） |
| R2 | **安慰剂检验**       | 把处理时间随机改到 2017/2018（保留处理组不变），或随机抽取“伪处理组”，重复 100–500 次，看伪估计分布    | 伪估计均值≈0，远离真实估计    |
| R3 | **替换结果变量**     | 用`labor_productivity`（或 `log(labor_productivity)`）替代 `log_tfp` 重跑主回归                     | 系数方向与显著性基本一致       |
| R4 | **改变控制变量集合** | ① 不加控制变量；② 加满控制变量；③ 加入`firm_size`；对比系数                                          | 系数变化小（如量级基本稳定）   |
| R5 | **改变聚类层级**     | ① 聚类到`industry`；② 聚类到 `province`；③ 二维聚类（firm + year）                                 | 标准误变化不大，显著性基本保持 |
| R6 | **极端值处理**       | 对`log_tfp` 做 1%/99% winsorize（或双侧截尾 1%）后重跑                                                  | 系数基本不变                   |
| R7 | **样本调整**         | ① 剔除电子行业（处理最集中）；② 剔除最大/最小 5% 企业；③ 仅保留 2018–2022 缩短窗口                    | 系数基本不变                   |

> 提示：这 7 项都是“同一套能力、不同设定”。你可以让 AI 用**一个脚本**批量生成，但要**逐张保存独立 Prompt**——作业评分看的是你“会不会设计任务”，不是“跑得多快”。

### 2.4 研究主题特定的稳健性检验

这些检验针对“数字化转型 → 企业生产率”这个**特定研究主题**，是区分本作业与“随便跑个 DID”的地方。

| #  | 检验                                                     | 为什么针对本主题                                                           | 统计设定（提示）                                                                                                                                                           |
| :- | :------------------------------------------------------- | :------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1 | **处理变量的测量方式**                             | “是否数字化”用 0/1 可能太粗，结果可能依赖测度                            | 用**数字化强度**替代 `digital`：如对处理企业按其 `managerial_capability`（或 `firm_size`）标准化构造连续强度，对照组为 0；解释“强度越大、效应越大的边际含义” |
| T2 | **异质性检验**                                     | 数字化对不同类型的效应可能不同，主题文献高度关注                           | 分别对 ① 行业（电子 vs 纺织）、② 所有制（SOE vs 非 SOE）、③ 规模（中位数以上/以下）做分组回归，报告组间差异                                                             |
| T3 | **机制检验：能力互补性**（替代原 Matlab 理论模型） | 课堂演示用结构模型讲“管理与数字化的互补性”；本作业用数据直接检验同一假设 | 在主回归中加入交互项`digital × managerial_capability`；若交互项显著为正，支持“高能力企业从数字化获益更多”的互补性机制。**不引入任何 Matlab 代码**               |
| T4 | **排除竞争性解释**                                 | 处理组可能恰好处在快速增长的行业/地区（行业冲击），被误认为数字化效应      | 加入`industry × year` 固定效应（或再加 `province × year`），吸收行业/地区层面的共同冲击                                                                              |

### 2.5 每项检验的产物要求

每完成一项检验，写入对应 Markdown（放在 `prompts/robustness/`）：

```markdown
# 稳健性检验：R1 平行趋势正式检验

## 检验目的
[一句话：这条检验想排除什么威胁]

## Prompt（四要素）
[你实际发给 AI 的 prompt 全文]

## 结果摘要
- 处理前系数联合检验：F = …，p = …
- 事件研究图：处理前是否平坦？

## 我的观察
- 符合预期 / 异常之处
- 如果异常，可能原因是什么？下一步怎么改？
```

### 2.6 本部分汇总产物

- `prompts/robustness/R1.md` … `T5.md`（每项一张，Markdown）
- `output/robustness_summary.md`：一张汇总表，横轴为 R1–R7 / T1–T5，纵轴为“结论是否稳健 / 观察 / 判断”

## 4. Part C：设计一个综合评估 Agent

### 4.1 任务要求

设计一个**综合评估 Agent**，它能对“主结果 + 全部稳健性检验结果”**结合研究主题**进行
**流程化的综合评估**，而不是只堆数字。

- 文件：`.claude/agents/eval-did-robustness.md`
- 建议名称：`eval-did-robustness`（综合评估 Agent）
- 至少要包含：目标、输入、工作步骤、输出模板、边界、验证方式

### 4.2 综合评估流程（六步）

| 步骤          | 做什么                                                                                                          | 输出             |
| :------------ | :-------------------------------------------------------------------------------------------------------------- | :--------------- |
| S1 读结果     | 读`output/stata_did_results.csv`、`python_did_results.csv`、`output/robustness_summary.md` 及各项检验输出 | 主结果与检验清单 |
| S2 汇总判定   | 把每项检验判定为 通过 / 警示 / 失败，给出依据                                                                   | 稳健性判定表     |
| S3 结论稳定性 | 主效应是否在所有设定下方向一致、显著性是否保持                                                                  | 稳定性结论       |
| S4 残余威胁   | 结合研究主题评估残余识别威胁（平行趋势、溢出、测量误差、样本选择……哪些仍未排除）                              | 威胁清单         |
| S5 主题解读   | 结合“数字化转型 → 生产率”主题解读异质性/机制发现（如 T3 互补性、T2 异质性），说明含义与边界                  | 主题解读段落     |
| S6 写作建议   | 基于 S3–S5 给出论文写作的具体建议：哪些话能说、哪些不能说、需要怎样措辞                                        | 写作建议         |

### 4.3 评估报告模板（Agent 输出）

```markdown
# DID 稳健性综合评估报告

## 1. 主结果
- DID 系数：…（聚类标准误 …）

## 2. 稳健性判定表
| 检验 | 判定（通过/警示/失败） | 依据 |
|:---|:---|:---|
| R1 平行趋势 | … | … |
| … | … | … |

## 3. 结论稳定性
[主效应在哪些设定下稳健 / 不稳健]

## 4. 残余威胁
[结合主题列出仍未排除的威胁]

## 5. 主题解读
[异质性与机制发现的含义、边界]

## 6. 对论文写作的建议
[具体到能写什么、不能写什么]

## 边界声明
[合成数据、不虚构文献、由研究者最终判断]
```

### 4.4 边界要求

- Agent 只做**评估与建议**，不直接改 `paper/`（可用 rules/hooks 或 Agent 内部约束保证）。
- Agent 必须输出**边界声明**；不得越过合成数据结论边界。
- Agent 遇到缺失/不明确的输入时，应**停下询问**，而不是编造。

## 6. Part E：两轮迭代（≥ 2 轮）

### 6.1 什么是“迭代”

迭代 = **观察输出 → 记录问题 → 修订 Prompt/Skill/Agent → 重新运行 → 对比**。
迭代不是“重跑一遍”，而是“**因为发现了具体问题，所以改变了设计**”。
评判标准是：第二轮比第一轮在**可信度、可迁移性、可审计性**上更好了。

### 6.2 迭代要求

至少做 **2 轮**，且至少覆盖 **Skill 与 Agent 各一轮**（可分开做）：

- **第一轮**：完成 Part A–D 的初版。仔细记录你观察到的问题——AI 哪里跑偏了？
  哪里过度自信？哪里不够通用？哪里越界了？
- **第二轮**：针对第一轮的问题修订（改 Prompt 措辞、改 Skill 的步骤/检查清单、
  改 Agent 的流程/边界），重新运行，记录改进。
- **第三轮以上（可选加分）**：把 Skill/Agent 拿到**另一个研究主题**（如虚构一个
  “最低工资对就业”数据集，或用自己的一个小数据集）上试跑，检验一般适用性。

### 6.3 参考示范

以下只是**示范过程**，不是让你照抄的答案。两轮迭代通常围绕
**“从具体项目专用 → 到一般可迁移”** 这条主线。

**示范一：Skill 的两轮迭代**

- 第一轮（问题：硬编码、不通用）

  ```markdown
  ## 工作步骤
  1. 运行 python scripts/analyze_did.py 复现主结果
  2. 读取 data/raw/digital_transformation_firm_panel.csv
  3. 用 log_tfp ~ digital + 固定效应 做 R1–R7 检验
  ```

  → 观察发现的问题：路径与变量名写死（`digital`、`log_tfp`），换一个研究主题就失效；
  没有“先读 README 识别变量”的步骤；没有强制把结果与 Prompt 存为 Markdown。
- 第二轮（改进：自描述数据、用占位符、可迁移）

  ```markdown
  ## 工作步骤
  1. 读取 README 与数据，识别结果变量 y、处理变量 D、个体 id、时间 t（在 README/注释中确认）
  2. 复现主回归（提示：reghdfe / PanelOLS；聚类层级在 README 或代码注释中确认）
  3. 按检查清单逐项做稳健性检验，输出结果表与图到 output/
  4. 每项检验把 Prompt 与观察存为 prompts/robustness/*.md
  ```

  → 第二轮观察：同一份 Skill 换一个数据也能执行，因为关键信息（y、D、id、t）由 AI 先自读数据获得。

**示范二：Agent 的两轮迭代**

- 第一轮（问题：只堆数字、不结合主题）

  → 观察：Agent 输出一张“系数表 + 是否显著”的清单，但说不清“这对数字化转型研究意味着什么”，
  也没有指出残余威胁，更没有给论文写作建议。
- 第二轮（改进：加入主题解读与威胁评估）

  → 在流程中加入 S4（残余威胁）与 S5（主题解读）：Agent 会结合处理机制（能力互补性）、
  数据特征（同步处理、行业冲击）判断哪些威胁仍未排除，并给出“论文里哪些话能说、哪些不能说”。

### 6.4 迭代反思文档模板（提交物）

```markdown
# 迭代反思（≥2 轮）

## 第一轮
- 我观察到的关键问题：[AI 哪里跑偏/越界/不通用？举例]
- 我做的修订：[改了 Prompt/Skill/Agent 的哪一部分，怎么改]
- 证据：[修订前后的输出对比 / git log 相关 commit]

## 第二轮
- 我观察到的关键问题：…
- 我做的修订：…
- 证据：…

## 一般适用性论证
- 换一个研究主题，我的 Skill/Agent 需要改哪里？不需要改哪里？
- 这说明我的设计是“可迁移的制度”还是“本项目的定制脚本”？
```

## 7. Part F：Git 版本控制要求

### 7.1 分支策略

- 每个 Part 一个分支（见 1.3 表），**在分支上做任务，审查后再合并回 main**。
- 让 AI 做探索性改动前，先要求它创建分支（对应 Day 1 的“AI 协作安全网规则 ③”）。

### 7.2 diff 审查

- 接受任何 AI 改动前：`git diff` 逐行审查（对应规则 ②“先 diff 再接受”）。
- 每个任务完成后，在 `audit-log.md` 记录：工具、任务、接受的输出、拒绝或修改的输出、验证方式。

### 7.3 commit 规范

- 用约定式提交：`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`。
- message 写清楚“做了什么、为什么”。

### 7.4 最终展示

- 提交物中附一段 `git log --oneline --graph --all` 的输出（可截图或文本），
  应能看出：每个任务一个分支、合并回 main、AI 改动可追溯。
