# 评分标准：数字化转型与企业生产率的 DID 稳健性检验与论文完善

**总分**：100 分
**评判原则**：重点看**设计质量与反思深度**，不是“跑了多少检验”。
同一项检验跑了 5 遍但不会解释，不如 1 遍但讲清楚了为什么、发现了什么、怎么改。

## D1 稳健性检验覆盖与合理性（30 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 优秀 | 27–30 | 完成全部 R1–R7 与 T1–T4（含可选 T5）；每项检验的**统计设定正确、判断标准清晰**；汇总表对每项给出“结论是否稳健”的判断与依据；识别目标（estimand）写得到位 |
| 良好 | 22–26 | 完成大部分检验（≥9 项）；个别设定有瑕疵但判断合理；汇总表基本完整 |
| 及格 | 16–21 | 完成约一半检验；部分检验“跑了但没说清含义”；识别目标较粗略 |
| 不及格 | 0–15 | 检验数量明显不足，或设定错误（如把处理后变量放进控制组、忽略聚类），或**越过合成数据边界下因果结论** |

> 红线：T3 机制检验若出现任何 Matlab 代码/结构模型，该维度扣 5 分（本作业明确不使用）。

## D2 Prompt 设计质量（15 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 优秀 | 13–15 | 每张 Prompt 四要素完整（目标/边界/验证/汇报）；边界明确（合成数据、只读、不虚构文献）；验证可执行 |
| 良好 | 10–12 | 四要素基本齐全；个别 Prompt 边界或验证含糊 |
| 及格 | 7–9 | 有目标与边界，但验证/汇报缺失较多 |
| 不及格 | 0–6 | Prompt 多为“帮我做 DID”式一句；无法复现 |

## D3 Skill 设计质量（15 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 优秀 | 13–15 | 六模块完整；**不硬编码路径/变量**（先读数据自识别）；有“如何迁移”一节；与裸 Prompt 的对比记录具体 |
| 良好 | 10–12 | 六模块基本完整；仍有少量硬编码；有对比记录 |
| 及格 | 7–9 | 结构不全或高度依赖本项目；对比记录模糊 |
| 不及格 | 0–6 | 只是把一篇 Prompt 改了名；或无法迁移到其他研究 |

## D4 Agent 设计质量（15 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 优秀 | 13–15 | Agent 有清晰流程（读结果→判定→稳定性→残余威胁→主题解读→写作建议）；输出结构化报告；**结合研究主题**给出判断而非堆数字；有边界与验证 |
| 良好 | 10–12 | 流程较完整；主题解读偏弱或报告较散 |
| 及格 | 7–9 | 能汇总数字，但缺乏“结合主题的综合评估”；报告像表格清单 |
| 不及格 | 0–6 | 无流程、无边界；或输出越界因果结论 |

## D5 论文完善质量（10 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 优秀 | 9–10 | 新增“稳健性检验”小节结构完整；结果表述与评估报告一致（区分相关/因果）；讨论与局限如实；LaTeX 编译出 PDF；引用经核查、无虚构 |
| 良好 | 7–8 | 主要要求达成；个别表述偏强或文献核查记录不足 |
| 及格 | 5–6 | 有稳健性内容但组织粗糙；或编译依赖他人/未出 PDF |
| 不及格 | 0–4 | 没有新增稳健性小节；或把合成数据结果写成真实因果证据 |

## D6 迭代与反思深度（10 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 优秀 | 9–10 | 至少 2 轮、每轮有“观察问题→修订→证据”；一般适用性论证具体（换主题试跑或明确说明改动点） |
| 良好 | 7–8 | 2 轮迭代完成；修订有依据，但证据或一般适用性论证略薄 |
| 及格 | 5–6 | 有 2 轮记录但更像“重跑”而非“因问题而改” |
| 不及格 | 0–4 | 无迭代记录，或把第一轮结果直接当最终结果 |

## D7 Git 版本控制规范（5 分）

| 档位 | 分数 | 行为描述 |
|:---|:---:|:---|
| 达标 | 5 | 每任务一分支；提交前有 diff 审查；commit message 规范；`git log --graph` 可展示完整历史；`audit-log.md` 有记录 |
| 部分 | 3 | 有 Git 历史但分支/审查/审计不完整 |
| 未达标 | 0 | 无 Git 历史，或 .git 缺失/单一大 commit |
