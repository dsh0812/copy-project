# DID 安慰剂检验 Skill

## 适用场景

当任务满足以下任一条件时，直接调用本 Skill：

- 需要验证 DID 估计是否只是偶然显著
- 需要做 placebo test / fake treatment test / random treatment timing test
- 需要检验处理效应是否被时间趋势、未观测冲击或选择性处理所驱动
- 研究对象是双重差分或事件研究设计，且已具备基础 DID 回归
- 需要在不硬编码项目变量的前提下，适配到新研究主题

---

## 1. 触发条件

调用本 Skill 的典型信号：

- “请做 DID 的安慰剂检验”
- “验证是不是伪阳性”
- “随机化处理时间，看看估计是否仍然显著”
- “检验是否存在 pretrend / time-varying confounding”
- “是否有未观测冲击导致 DID 系数偏大”

### 先判断是否适合做 placebo

只有在下列条件成立时才值得继续：

- 研究中已确认处理变量、个体维度、时间维度和核心控制变量
- 基础 DID 回归已跑通，至少能得到主估计系数
- 目标是“验证因果识别假设”，而不是单纯做另一轮模型拟合

---

## 2. 背景知识

### DID 的核心识别命题

在 DID 中，安慰剂检验的核心问题不是“系数是否显著”，而是：

- 如果处理事实上并不存在，是否仍可能得到一个类似大小的系数？
- 如果伪处理效应的分布集中在 0 附近，说明真实估计更可信
- 如果伪处理效应经常接近真实效应，说明设计可能受共时趋势或选择性处理影响

### 常见 placebo 设计

常见做法包括：

1. 随机化处理时间：把实际处理时间前移或随机分配到其他年份
2. 随机伪处理组：从未处理单位中随机抽取虚拟处理组
3. 处理前年份 placebo：把“真实处理”放到处理前的年份，检验是否存在预期效应
4. 伪结果变量：用与真实结果相关但不会受处理影响的变量做测试

### 关键输出指标

每次 placebo 检验至少记录：

- 真实 DID 系数
- 伪处理系数均值
- 伪处理系数标准差
- 真实系数是否落在伪分布尾部
- 失败比例或超过阈值的概率

### 通用解释标准

- 伪估计均值接近 0，且真实系数明显偏离伪分布：说明安慰剂检验通过
- 伪估计分布与真实系数高度重叠：说明结果可能不稳健，需检查时间趋势与选择性处理
- 真实系数落在伪分布中心附近：对 causal interpretation 要保持谨慎

---

## 3. 执行步骤（推荐工作流）

### Step 1：确认基本 DID 设定

先读数据并确认：

- outcome_var：结果变量
- treatment_var：处理变量，通常为 0/1
- unit_id：个体/企业/地区编号
- time_id：时间维度
- controls：控制变量集合
- cluster_id：聚类标准误的维度

不要在还没确认这些变量时直接跑 placebo。

### Step 2：保留真实主回归作为参照

先复现基础 DID：

- 估计真实 treatment effect
- 保存系数、p 值、标准误、样本量
- 作为后续 placebo 对照基准

### Step 3：生成 placebo 试验

推荐方式：

- 保持处理组与对照组身份不变
- 随机指定处理时间（例如提前到 2017/2018）
- 或从单位中随机抽样伪处理组
- 或把处理发生时间置于处理前年份

必须保证：

- 仅在副本数据上做随机化
- 设置随机种子以保证可重复
- 不修改原始数据文件

### Step 4：重复抽样并估计

建议至少执行：

- 200 次 placebo 回归（最小可接受）
- 若样本足够大，可做 500 次，取更稳定结果

每次记录：

- 伪处理系数
- 标准误
- p 值
- 是否超过真实主效应绝对值

### Step 5：生成分布与诊断

输出：

- placebo 伪系数分布图
- 均值、标准差与分位数
- 真实效应在分布中的位置
- 关键判断：真实效应是否明显偏离 0 及伪分布中心

### Step 6：写出结论

结论必须可审计，写成明确句式：

- “Placebo 检验支持真实处理效应不由随机噪音驱动”
- “Placebo 分布较集中于真实效应附近，需谨慎解释因果”
- “伪处理系数平均接近 0，但真实效应并未明显偏离伪分布，表明设计仍可能受时间趋势影响”

---

## 4. 检查清单（必须排查）

在执行 placebo test 时，至少检查以下问题：

### 数据问题

- 是否在处理前后发生了结构性变化？
- 是否存在缺失值、编码错误或重复单位？
- 是否所有个体在所有年份都有观测？

### 设定问题

- 处理变量是否真的被随机指定？
- 处理时间是否与真实研究设计一致？
- 伪处理分配是否破坏了真实机制而不是人为制造“好看结果”？

### 统计问题

- 是否有 singular matrix / rank deficiency
- 是否出现 NaN / inf / invalid sqrt
- 是否标准误聚类层级与主回归一致
- 是否对 placebo 结果只看显著性而没有看分布位置

### 解读问题

- 不要仅凭“伪系数不显著”就说因果可信
- 不能把 placebo 通过当成“证明无遗漏变量”
- 必须把结论写清楚：支持还是仅提示风险

---

## 5. 边界条件

### 不能做的事

- 不要修改原始数据文件或输出基础主结果
- 不要在未确认基础 DID 后直接做 placebo
- 不要用“看起来合理”的伪处理时间替代真实随机化
- 不要把“没有显著的 placebo”解释成“无内生性问题”
- 不要把同一组虚拟处理重复设定成“多次看起来都支持”的审稿技巧

### 什么时候应当停止

- 如果基础 DID 模型本身不稳定，先修正主回归
- 如果样本太小、时间太短、处理组很少，placebo 分布会失真
- 如果处理不是清晰的单一 timing，而是渐进式 rollout，需改用更合适的设计

---

## 6. 验证方式（如何证明做对了）

### 最基本验证

一份合格的 placebo 检验应至少包含：

- 真正的 DID 主回归系数
- placebo 伪处理分布图
- 伪估计均值与标准差
- 真实效应相对伪分布的位置
- 对结果的解释结论

### 代码层验证

运行时应确认：

- 脚本能在同一环境中稳定重复生成相同分布
- 数据和回归公式一致
- 未修改原始数据
- 结果文件已落盘到 output 或对应目录

### 逻辑层验证

检查以下问题：

- 伪处理分布是否真的围绕 0
- 真实系数是否显著偏离了伪分布中心
- 结论是否符合实际结果，而不是“主观描述”

### 套用标准

若满足以下条件，可认定安慰剂检验完成：

1. placebo 运行成功，且结果可复现
2. 真实系数与伪分布位置已明确标注
3. 结论与分布特征一致
4. 写出相应的研究判断，不越界宣称因果

## 8. 如何迁移到新研究主题（一般适用性）

这份 Skill 的价值在于它不是“为某个具体研究项目定制”，而是可迁移到新 DID 应用中。

### 需要调整的部分

- outcome_var：从研究结果变量替换为新的因变量
- treatment_var：从处理变量替换为某一政策/冲击/干预变量
- unit_id / time_id：换成新的个体和时间维度
- controls：按新的研究文献选择控制变量
- cluster_id：根据样本结构更改聚类层级

### 不需要调整的部分

- placebo 的逻辑结构
- 一个真实 DID 基线 + 一组随机化 placebo 的步骤
- 伪分布解释方法
- 汇总、结论和审计框架

也就是说：

- 研究主题变了，方法没变
- 应用对象不同，识别逻辑相同
- 关键是“随机伪处理 + 分布比较 + 因果解释”这一套制度，而不是具体变量名

这是本 Skill 对 assignment.md 中“general applicability / 反复使用 / 可迁移”要求的核心体现。

---

## 9. 一句总结

本 Skill 的目标不是让 AI 一次“跑出一个系数”，而是让 AI 按照 DID 因果识别要求，系统地执行 placebo 检验，并输出可复核、可迁移、可解释的证据链。
